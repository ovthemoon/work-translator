### client-dev-01 · 클라이언트 → 개발자 · 실무자 수준 · 11.8초 ✅

> 버튼 하나만 추가하면 되는 거 아니에요?

**번역:** 겉으로는 버튼 하나만 추가하는 것처럼 보이지만, 실제로는 화면 배치, 클릭 시 동작, 데이터 연결, 예외 처리까지 함께 필요할 수 있어요.

**되물을 질문:**
- 버튼을 누르면 어떤 화면이나 동작이 일어나야 하나요?

**주의:** '버튼 하나'라는 말 때문에 작업량이 과소평가될 수 있어요. 실제로 필요한 동작과 연결 범위를 먼저 확인하세요.

### client-dev-02 · 클라이언트 → 개발자 · 실무자 수준 · 2.1초 ✅

> 네이버처럼 만들어주세요

**번역:** 네이버처럼 만들어 달라는 요청이에요. 다만 '네이버처럼'이 화면 구성, 검색 기능, 로그인/회원가입, 뉴스·콘텐츠 배치, 반응형 구조 중 무엇을 말하는지 원문만으로는 알 수 없어요.

**되물을 질문:**
- 네이버의 어떤 부분을 참고하고 싶으신가요? 예를 들면 메인 화면 구성, 검색, 로그인, 콘텐츠 배치 중 무엇인가요?

**주의:** '네이버처럼'은 범위가 매우 넓어서, 그대로 받아들이면 작업 범위가 계속 늘어날 수 있어요. 참고할 화면이나 기능을 먼저 하나로 좁혀야 해요.

### client-dev-03 · 클라이언트 → 개발자 · 실무자 수준 · 4.4초 ✅

> 일단 대충 만들어놓고 나중에 고치죠

**번역:** 일단 작동하는 버전을 먼저 만들고, 나중에 다듬거나 수정하자는 뜻이에요. 다만 '대충'의 범위가 어디까지인지, 나중에 고칠 부분이 UI만인지 기능·데이터까지인지에 따라 작업 방식이 달라져요.

**되물을 질문:**
- 나중에 고칠 부분은 화면 디자인만인가요, 기능이나 데이터 처리도 포함인가요?

**주의:** 나중에 고친다고 정해 두면, 지금 만든 구조가 나중에 수정하기 어려운 방식으로 잡힐 수 있어요. 어디까지 임시로 두고 어디는 제대로 할지 먼저 정하는 게 좋아요.

### client-dev-04 · 클라이언트 → 개발자 · 실무자 수준 · 2.6초 ✅

> 이거 왜 이렇게 오래 걸려요? 그냥 복사 붙여넣기 아닌가요?

**번역:** 작업이 왜 오래 걸리는지, 그리고 정말 복사·붙여넣기처럼 간단한 일인지 궁금해하시는 거예요. 실제로는 기존 코드나 화면과 맞춰서 넣어야 해서 생각보다 손이 가는 경우가 많아요.

**요청 분리:** 작업 소요 시간이 긴 이유를 설명해 달라는 요청 / 복사·붙여넣기 수준의 단순 작업인지 확인해 달라는 요청

**되물을 질문:**
- 어떤 화면이나 기능을 말씀하시는 건가요?
- 지금 어디까지 진행됐고, 어떤 부분에서 막히고 있나요?

**주의:** '그냥 복사 붙여넣기'라는 말은 실제 작업 범위를 과소평가하게 만들 수 있어요. 정확히 어떤 작업인지 먼저 맞춰 보는 게 좋아요.

### client-dev-05 · 클라이언트 → 개발자 · 실무자 수준 · 1.7초 ✅

> 다른 데는 이거 하루면 한다던데

**번역:** 다른 업체는 이 작업을 하루 만에 끝낸다고 들었다는 말이에요. 실제로는 작업 범위, 기존 상태, 준비물 유무에 따라 기간이 크게 달라질 수 있어요.

**되물을 질문:**
- '이거'가 정확히 어떤 작업인지 범위를 알려 주실 수 있나요?
- 다른 곳에서 말한 조건과 지금 상황이 같은가요?

**주의:** 비교 대상이 같은 조건인지 확인하지 않으면, 일정 기대치가 어긋나서 서로 오해가 생길 수 있어요.

### client-dev-06 · 클라이언트 → 개발자 · 실무자 수준 · 1.9초 ✅

> 홈페이지가 느린 것 같아요

**번역:** 홈페이지가 느리다는 피드백이에요. 다만 '느리다'는 느낌만으로는 원인을 특정하기 어려워서, 어떤 페이지·어떤 상황에서 느린지, 체감 속도인지 실제 측정값인지 확인이 필요해요.

**되물을 질문:**
- 어떤 페이지가 느린가요?
- 언제 느린가요? (처음 열 때, 클릭 후 이동, 특정 기기 등)
- 느리다고 느끼는 기준이 있나요? (예: 3초 이상 기다림)

**주의:** '느리다'는 표현만으로는 서버 문제인지, 이미지·스크립트 문제인지, 네트워크 문제인지 알 수 없어요. 원인 확인 없이 바로 수정하면 불필요한 작업이 될 수 있어요.

> 모바일에서 좀 이상해요

**번역:** 모바일 화면에서 무언가 이상하게 보인다는 보고예요. 다만 '이상하다'만으로는 어떤 화면, 어떤 기기, 어떤 동작에서 문제가 나는지 알 수 없어요.

**되물을 질문:**
- 어떤 화면이나 기능에서 이상하나요?
- 어떤 기기·브라우저·앱에서 보셨나요?
- 이상한 모습을 사진이나 영상으로 보내주실 수 있나요?

**주의:** '모바일에서 이상해요'만으로는 재현이 안 돼서, 기기·화면·상황을 먼저 확인해야 불필요한 작업을 줄일 수 있어요.

### client-dev-08 · 클라이언트 → 개발자 · 실무자 수준 · 2.4초 ✅

> 관리자 페이지에서 제가 다 수정할 수 있게 해주세요

**번역:** 관리자 페이지에서 클라이언트가 직접 내용을 수정할 수 있는 기능을 만들어 달라는 요청이에요. 다만 '다'가 어디까지인지, 어떤 항목을 어떤 권한으로 수정하는지는 원문만으로는 알 수 없어요.

**되물을 질문:**
- '다'가 구체적으로 어떤 항목들인가요?
- 수정 권한은 특정 관리자만인가요, 여러 역할인가요?

**주의:** '다 수정 가능'은 권한·검수·실수 방지까지 함께 설계해야 해서 범위가 커질 수 있어요. 먼저 수정할 항목과 권한을 정리하세요.

### client-dev-09 · 클라이언트 → 개발자 · 실무자 수준 · 2.5초 ✅

> 결제 기능 넣는 거 얼마나 걸려요?

**번역:** 결제 기능을 추가하는 데 걸리는 개발 기간을 묻는 질문이에요. 다만 결제 방식, 연동 범위, 기존 시스템 상태에 따라 기간이 크게 달라져서, 지금 정보만으로는 정확한 답을 드리기 어려워요.

**되물을 질문:**
- 어떤 결제 방식을 쓰나요? (카드, 간편결제, 계좌이체 등)
- 직접 결제창을 띄우나요, 아니면 결제 대행사(PG) 링크를 쓰나요?
- 기존에 결제 관련 코드나 연동이 이미 있나요?

**주의:** '결제'는 단순 화면 추가가 아니라 금액·보안·환불·취소 처리까지 이어질 수 있어서, 범위를 먼저 정하지 않으면 일정이 쉽게 늘어날 수 있어요.
